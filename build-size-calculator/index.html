¿Por qué importa el tamaño del build?

  • Tasa de instalación: Cada MB reduce ~5% descargas. 500MB vs 100MB = 20% menos usuarios
  • Almacenamiento de dispositivo: Móviles tienen espacio limitado. Compite con aplicaciones rivales
  • WiFi vs Mobile: Con datos móviles, usuarios cancelan descargas > 50MB
  • Store Optimization: Google Play/App Store priorizan apps más pequeñas
  • Tiempo de boot: Builds más pequeños = carga más rápida al iniciar

🎯 Recomendaciones de Optimización

📚 Guía de Reducción de Build Size

  • Compresión de Texturas: ASTC/ETC2 (móvil), BC1/BC3 (PC). Reduce 70-80% vs RGBA.
  • Mesh Compression: Activa en Project Settings. Reduce 20-50% dependiendo de precisión.
  • Audio Compression: Vorbis (móvil), WAV (PC). MP3 es legacy.
  • LZ4 Compression: Compression en Player Settings. 30-40% reducción pero más CPU en startup.
  • Asset Bundles: Descarga bajo demanda. Estrategia: core gameplay base + contenido cosmético bajo demanda.
  • Engine Stripping: Remueve módulos no usados (Physics, Navigation, etc.). Ahorra 20-100MB.
  • Managed Code Stripping: Remueve código no referenciado. Usa Link.xml si necesitas preservar tipos dinámicos.
  • WebGL optimization: Minificación, brotli compression. Target WebGL Server.

💡 Tips Pro para Builds Pequeños

  • 🎨 Usa procedural generation para content en lugar de assets pregenerados
  • 📱 Targets: ARMv7 o ARM64 por separado (no Universal) para APK. AAB permite Google optimizar.
  • 🔗 Linked.xml: Especifica qué código preservar si usas Reflection
  • 🗂️ Categoriza assets: gameplay crítico en build, resto en bundles
  • ✂️ Remueve assets no usados: uso Asset Browser y Addressables para auditar
  • 🎬 Video: Usa WebM (VP9) para web, H.264 para móvil
  • 📦 CDN: Hostea asset bundles en CDN, no en Google Play/App Store
